# XFlow → TRON2/Wuji2 执行层设计（仅设计，未实现发送）

本页定义第二阶段如何把已经验收的短时目标段接入现有 replay 控制链。当前仓库没有
Robot、Hands、ServoP、ServoJ、Wuji command publisher 或 `request_emgy_stop` 调用；本文也
不改变这个事实。

## 责任边界

执行系统拆成四个单向层：只读观测进程、推理/重定向规划器、已验收目标队列、唯一硬件
发送器。观测进程只生成带 ROS header epoch 时间和本地 monotonic 接收时间的不可变快照；
规划器只输出 `TimedChunk`；所有坐标、限位、速度、IK、时效检查通过后，队列才接受它；
只有发送器拥有控制会话。规划线程、ROS 回调和推理客户端永远不能直接发布硬件目标。

每次最多一项推理/规划任务。新段用 `replace_future` 只替换尚未执行的未来，交接区间使用
同一时钟的五次 smoothstep、XYZ/手关节线性插值和四元数最短弧 SLERP。`initial_lead` 必须
覆盖推理 p95、重定向、IK、安全检查和调度 margin；当前配置保留 150 ms planning reserve，
真实值要依据在线持续测量重新认证。响应身份、deployment id、session/sample、图像空间、
时间表或检查任一不一致，整段不可进入队列。

## 启动与接管

未来实现复用 `replay_hand` 已验证的分阶段流程：保持 Wuji 当前实测姿态；使用认证的
MoveJ/ServoJ 接近第一个 EEF；确认手臂静止、反馈健康且首段已在队列中；再由单一发送线程
切换至 ServoP。首段从实测状态到第一预测点做有限时 startup blend，不能把第一预测点当成
已达到的状态，也不能用上次命令冒充实测 q/EEF。

接管后，臂发送线程按控制器要求的固定周期从 50 Hz 已验收 EEF 轨迹插值，手保持 50 Hz。
用户已确定 `hh_*` 的 32 个输出点按 32 个 30 Hz 帧解释：第 `i` 点的截止时刻为
`exec_start + (i+1)/30 s`，32 点占 1.0667 s；没有 0.25 speed-scale 入口。模型原生
`keypoint_time_s` 只保留作诊断对照，不作为默认发送时钟。历史图仍按服务 info 的 4 个
相机帧（约 0.133 s）选取，不因执行时钟改成 16 帧。

## 队列、过期与停止

队列必须始终有明确的最后有效时刻，发送器禁止外推或无限 hold 旧预测：

- 新响应在 `now + planning_reserve` 前没有未来点：丢弃，不接管。
- 新段未覆盖完整 blend 和有用尾部：拒绝，保留原段的未执行安全前缀。
- 队列低于 margin：停止接收新的预测替换；若无法在最后有效点前补齐，先停止 ServoP，
  再通过反馈确认控制器进入 hold。
- 响应过期、deployment 改变、通信断开、IK/限位/速度/EEF_BOX 失败：该段不执行；已有
  队列只消费仍在有效期内且已验收的部分。
- 实测反馈非有限、超龄、跳变、控制器模式改变或跟踪误差持续超限：停止 ServoP 并验证
  controller hold；手保持最后一次已确认的安全实测附近目标，不能继续消费预测。

普通的模型质量拒绝、跟踪阈值拒绝和队列耗尽不应调用 `request_emgy_stop`。它们属于受控
停止/hold，应尽量保持高级开发者模式；`request_emgy_stop` 仅保留给确有碰撞、失控或控制器
无法进入安全 hold 的紧急情况。是否能在所有控制器故障下保持高级开发者模式必须通过厂家
接口和真机分阶段测试确认，不能由客户端假定。

## 监督与可审计性

发送器只接受不可变、带 hash/模型身份/时间策略的已验收段。每个 tick 记录目标时刻、发送
时刻、实测 EEF/q、控制器状态和队列余量；监督线程只读这些数据。不得把日志、碰撞模型或
无界 IK 放进高频发送临界区。所有退出路径都要记录究竟是规划拒绝、时效过期、反馈异常、
用户停止还是紧急停止。

进入硬件阶段前至少要完成：实时 Wuji state 恢复；41.5° 相机外参物理复核；模型输出在
1 rad/s 手/臂门槛下的策略（拒绝、滤波或更短前缀）确定；controller hold 不退出高级开发者
模式的台架验证；startup/underrun/断网/STALE_SESSION 故障注入。当前远端 dry-run 已发现
部分预测超过 1 rad/s，因此现阶段不能把生成的段标为 execution-ready。
